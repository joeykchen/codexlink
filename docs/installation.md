# Installation architecture

## User contract

Installation is one operation, not a checklist of platform packages. The user invokes the bootstrap script from a workspace; the script selects and verifies a self-contained release, installs it atomically, updates the user PATH, provisions Git when necessary, and launches `codexlink`.

```text
bootstrap script
  -> stable release asset name
  -> SHA-256 verification
  -> codexlink + cloudflared
  -> atomic user-local install
  -> PATH registration
  -> automatic Git provisioning when absent
  -> workspace onboarding
```

## Dependency policy

- **Go:** build-time only. End users download a precompiled binary.
- **cloudflared:** bundled in every supported release archive and also placed next to CodexLink.
- **ripgrep:** not required. Workspace search has a native Go implementation.
- **Git:** detected at installation. When absent, the installer invokes the available OS package mechanism automatically. Failure to provision Git does not disable non-Git MCP tools.
- **curl/wget/PowerShell:** treated as operating-system bootstrap facilities. Unix accepts either curl or wget; Windows uses built-in PowerShell HTTP and hashing APIs.

## Supported release targets

```text
darwin/amd64
darwin/arm64
linux/amd64
linux/arm64
windows/amd64
windows/arm64
```

Platform and asset conventions are defined once in `internal/distribution`. Unsupported targets fail before download or packaging.

## Security properties

1. Release packages and checksum files are fetched over HTTPS.
2. SHA-256 is checked before extraction.
3. Archive paths are generated by a path-safe packager.
4. Files are installed through temporary names and atomic replacement.
5. Executables are installed to a user-owned directory by default.
6. The installer never evaluates downloaded shell text from a release archive.
7. Version and repository overrides are explicit environment variables, which also make mirrors and enterprise distribution possible.

## Automation overrides

```text
CODEXLINK_INSTALL_DIR
CODEXLINK_VERSION
CODEXLINK_REPOSITORY
CODEXLINK_NO_START=1
CODEXLINK_SKIP_GIT=1
CODEXLINK_SKIP_PATH_UPDATE=1
CODEXLINK_BUNDLE_FILE
CODEXLINK_CHECKSUM_FILE
```

The final two variables provide an offline/test path without weakening checksum verification.
